# indexgap

> [English README](README.md) · это полная русская версия.

Контроль качества programmatic-конвейера: сотни однотипных страниц из данных,
которые должны попасть в индекс и привести трафик.

Отвечает на вопрос, ради которого всё и затевается: **конвейер отработал,
страницы лежат, а трафика нет — почему.**

Только стандартная библиотека Python 3.9+. Ни зависимостей, ни API-ключей,
ни платных подписок. Ничего не отправляется наружу без явного флага.

---

## Зачем

Инструментов, проверяющих одну страницу, много. Конвейер ломается иначе —
системно и незаметно:

* страница есть в sitemap, но на неё не ведёт ни одна внутренняя ссылка,
  и краулер до неё не доходит;
* триста страниц отличаются пятью словами, и поисковик оставляет в индексе одну;
* агент написал «12 лет на рынке» и «3500 заказов» — цифр нет ни в одной строке
  данных, но выглядит убедительно;
* `lastmod` у всех страниц равен дате сборки, поэтому ничего не значит;
* два ключа с одним смыслом дали две конкурирующие страницы;
* половина страниц глубже четырёх кликов от главной.

Глазами это не поймать: каждая страница по отдельности выглядит нормально.

## Установка

```bash
git clone https://github.com/borisowlexa2010-star/indexgap && cd indexgap
pip install -e .
```

После этого команда `indexgap` доступна из любого каталога — в том числе
из каталога вашего сайта.

Без установки работает `python3 -m indexgap …`, но **только из каталога пакета**.
На Windows, если `python3` открывает магазин приложений, используйте `py -3`.

Проверка:

```bash
indexgap --help
```

## Команды

Запускать из каталога своего проекта.

```bash
# 1. Разобрать семантику ДО генерации
indexgap plan keywords.csv --keyword keyword
indexgap plan keywords.csv --keyword keyword --out-dir content --write

# 2. Проверить сгенерированное (--dataset включает сверку фактов)
indexgap check ./content --site https://example.com --dataset keywords.csv

# 3. Собрать sitemap
indexgap sitemap ./content --site https://example.com --out-dir ./public

# 4. Сообщить об изменениях (по умолчанию — пробный прогон)
indexgap notify ./content --site https://example.com --key <свой-ключ>

# 5. Понять, где теряется трафик — по всем поисковикам сразу
indexgap doctor ./content --site https://example.com \
    --sitemap ./public/sitemap.xml \
    --indexed gsc.csv --indexed bing.csv --indexed yandex.csv

# 6. Прогнать сразу все свои сайты и найти общие грабли
indexgap portfolio projects.json --reports ./reports
```

`--site` — адрес сайта целиком, со схемой. Он же определяет главную страницу.

**Каталог должен соответствовать корню сайта.** Если страницы лежат в `./content`,
а на проде они доступны как `/uslugi/…`, то и запускать надо на `./content`,
а не на корне проекта: иначе все адреса сдвинутся на сегмент, ссылки перестанут
совпадать, и вы получите «все страницы сироты». Пакет это подозрение проверяет
и говорит вслух, но лучше не создавать ему работу.

Понимает и собранный HTML, и исходники в Markdown с фронтматтером. Кодировка
входных файлов определяется сама: cp1251 из русского Excel, UTF-16, BOM.

## Что именно проверяется

**До генерации** — точные дубли ключей, коллизии slug и одинаковые интенты.
Последнее важнее всего: два ключа с одним смыслом гарантированно дадут две
почти одинаковые страницы. Одинаковым считается совпадение значимых слов
после нормализации словоформ, поэтому «виза в сингапур» и «сингапур виза» —
это одна страница, а «виза в сингапур для россиян» — уже другая.

**После генерации — текст:**

| Что | Почему это важно |
|---|---|
| **Числа, которых нет в данных** | сверяются с исходной строкой и со всем датасетом. Число с единицей проекта — критичная находка, число с любым другим словом («12 лет», «25 тонн») — предупреждение. Число, которого нет во всём датасете, не прощается никогда, сколько бы страниц его ни повторяло |
| Одинаковый скелет заголовков | текст разный, структура одна — для поисковика это штамповка |
| Одинаковое начало текста | второй признак того же |
| Забытый бриф, `status: draft` | страница не дописана. В sitemap и в IndexNow черновики не попадают вовсе |
| Анкоры «здесь», «подробнее» | ссылка есть, смысла в ней нет |

Страница связывается со строкой датасета тремя способами: по `keyword`
во фронтматтере, по совпадению slug, а для собранного HTML — по заголовку.
Если подошли сразу две строки, сверка честно не делается: результат,
зависящий от порядка строк в CSV, хуже отсутствия результата. Следите
за строкой «Сверено с датасетом: N из M».

**После генерации — структура:**

| Что | Почему это ломает трафик |
|---|---|
| Почти-дубли и просто похожие страницы | поисковик оставляет в индексе одну из пары |
| Доля уникального текста | если шаблон вытеснил содержание, индексировать нечего |
| Тонкие страницы | меньше порога слов — кандидат на выбрасывание из индекса |
| Сироты и недостижимые | нет входящих ссылок → нет обхода → нет индексации |
| Глубина клика | глубже трёх кликов краулер ходит редко |
| `noindex`, `nosnippet`, чужой canonical | страница сама себя исключила, обычно по ошибке шаблона |
| Заголовки: нет H1, несколько H1 | поисковику нечем определить тему |
| Дубли title и description | склейка в выдаче |

До четырёхсот страниц сравнение попарное и точное. Дальше включается
MinHash с LSH-бэндингом, и группы очень похожих страниц сравниваются
с образцом группы — об этом отчёт говорит прямо, а не молчит.

Скорость честно, замерено на 5 001 странице: полный `check` — 22 секунды,
без текстовых проверок — 17, сборка sitemap — 4, разбор семантики
на 5 000 строк — 0,2. Пик памяти около 390 МБ. Это чистый Python без
зависимостей; если нужно быстрее, поднимите `exact_below`, уменьшите
`minhash_perms` или выключите текстовые проверки флагом `--no-content`.

Уникальность считается **по биграммам, а не по словам**. В узкой нише словарь
ограничен: «виза», «документы», «срок» законно стоят на каждой странице.
А вот повторяющиеся фразы — это уже шаблон. На выборке меньше восьми страниц
оценка не делается: результат менялся бы от одной добавленной страницы.

Числа со словами, которых нет в данных, — «12 лет», «25 тонн», «3500 заказов» —
собираются в одну строку `check-by-eye` на страницу, уровень «мелочь». Это список
для просмотра глазами: часть таких чисел — обычная речь, часть — выдумка агента.
Счётные обороты («3 шага», «5 звёзд», «топ-10») в него не попадают.

**Машинная читаемость** (флаг `--no-aeo` выключает):

| Что | Почему |
|---|---|
| `nosnippet`, `max-snippet:0` | без права на сниппет страницы нет в ответах ИИ-поиска |
| robots.txt: OAI-SearchBot, PerplexityBot, ClaudeBot, GPTBot, Google-Extended | блокировка OAI-SearchBot исключает сайт из ответов поиска ChatGPT; Google-Extended на AI Overviews не влияет — это разные вещи |
| Пустой JS-каркас | краулеры ИИ-поиска не исполняют JavaScript |
| Прямой ответ в первом абзаце | его и цитируют; «в этой статье мы рассмотрим» цитировать нечем |
| Вопросные подзаголовки, списки, таблицы | формат «вопрос → ответ» извлекается заметно чаще |
| Валидность JSON-LD и совпадение FAQ с текстом | наличие разметки прироста не даёт, а вранье в ней — риск санкций |
| Машиночитаемые дата и автор | сигналы E-E-A-T; попутно ловит «обновлено сегодня» на трёхстах страницах |

**При публикации** — sitemap с шардингом после 45 000 URL и честным `lastmod`,
который меняется только при изменении текста, заголовка или описания. Правка
пункта меню не помечает изменённым весь сайт. IndexNow отправляет только
изменившееся, а не весь sitemap на каждый деплой.

## Портфель: несколько сайтов за один прогон

Если сайтов несколько, отдельные отчёты отвечают только на вопрос «что не так
у этого». Портфель отвечает на другой, которого в них не видно: **что ломается
одинаково везде.** Одна и та же дыра в перелинковке на четырёх разных нишах —
это уже не баг проекта, а свойство того, как эти проекты собираются.

```json
{
  "projects": [
    {"name": "visa",    "root": "../visa/content",   "site": "https://visa.example",
     "profile": "catalog", "dataset": "../visa/keywords.csv"},
    {"name": "eventiq", "root": "../eventiq/events", "site": "https://eventiq.example",
     "profile": "events"},
    {"name": "rumors",  "root": "../rumors/content", "site": "https://rumors.example",
     "profile": "ugc"},
    {"name": "reloca",  "root": "../reloca/out",     "site": "https://reloca.example",
     "profile": "product"}
  ]
}
```

```
  · visa      2933 стр.  критично  412  внимание  980  [catalog]
  · eventiq    840 стр.  критично   61  внимание  210  [events]
  · rumors    5100 стр.  критично    0  внимание  430  [ugc]
  · reloca      34 стр.  критично    2  внимание   18  [product]

Общие грабли на страницах (доля страниц проекта):
  orphan       3 проекта: visa 41%, eventiq 38%, reloca 35%
  same-opening 2 проекта: visa 62%, eventiq 55%

Общее в настройке сайтов:
  ai-crawler-blocked   visa, eventiq, rumors
```

Доля важнее абсолютного числа: сто находок на трёх тысячах страниц и десять
на двадцати — одна болезнь разной громкости. Ошибка одного проекта не роняет
прогон: она попадает в отчёт строкой, остальные считаются дальше.

Пути внутри файла — относительно него самого, поэтому его удобно положить
рядом с репозиториями. Пример — в `examples/projects.example.json`.

## Профили типов контента

Пороги у каталога, афиши, ленты и лендинга разные не по вкусу, а по существу:
250 слов — норма для гайда и приговор для карточки события, а сверка фактов
бессмысленна там, где датасета нет вовсе. `indexgap profiles` печатает все четыре.

| Профиль | Для чего | Что меняется |
|---|---|---|
| `catalog` | страницы из строк данных: города, услуги, товары | сверка фактов главная; дубль от 0,80; тонкая — меньше 250 слов |
| `events` | афиша, расписания, площадки | дубль от 0,88 — две карточки одного тура законно похожи; тонкая — меньше 120 слов; включается `stale-event` |
| `ugc` | лента, обсуждения, отзывы | сверка фактов выключена целиком и об этом сказано вслух; дубль от 0,92 |
| `product` | десятки лендингов, а не тысячи страниц | дубли не главное; окупается AEO-часть |

Профиль задаётся флагом `--profile` или полем в описании портфеля. **Явная
настройка в `indexgap.json` всегда сильнее пресета.**

Отдельно про `events`: `stale-event` ловит прошедшее мероприятие, оставшееся
открытым для индексации. Это не про трафик, а про доверие — человек приедет
по такой странице на концерт, которого нет. У проверки есть льготный период
(по умолчанию 14 дней): отчёт о прошедшем — законный контент.

Отдельно про `ugc`: если по фактам нет находок, это не «всё хорошо», это
«сверять не с чем». Пакет говорит это отдельной строкой, и её надо читать.

## Воронка

Главное, ради чего стоит ставить:

```
Сгенерировано              58
Пригодно к индексации      56   (−2: noindex или canonical на другую страницу)
В sitemap                  56
Хотя бы в одном индексе    28   (−28: поисковик знает про URL, но не добавил)

Почему страницы не в индексе:
    7  сироты и недостижимые от главной  → добавить ссылки с хабовых страниц
   12  глубже допустимого клика          → поднять выше в структуре
    9  причина не установлена локально   → проверить статус в Search Console
```

Данные об индексации берутся из обычных экспортов панелей вебмастера —
Search Console, Bing Webmaster Tools, Яндекс.Вебмастер, Naver. Формат у всех
разный, URL есть у всех; какой это поисковик, пакет определяет по имени файла
и заголовкам, а при сомнении просит указать явно: `--indexed bing=export.csv`.
Молча слить две выгрузки в один индекс он не станет.

**Важная оговорка.** Экспорт «Страницы» из Search Console — это отчёт
о показах, а не об индексации: страница в индексе без показов туда не попадёт.
На новом сайте воронка из-за этого завышает потери.

Категорию «причина не установлена локально» пакет признаёт честно: часть причин
локально не определяется, и часто дело просто в том, что прошло мало времени.

## Поисковиков больше одного

Это не формальность, а разные диагнозы:

```
Хотя бы в одном индексе        9   (потеряно 3)
  из них в bing                9
  из них в google              5   (потеряно 4)
  из них в yandex              7   (потеряно 2)

Сравнение поисковиков:
    3  везде
    4  нет только в google  → другие поисковики страницу приняли, значит она
                              доступна и валидна. Причина на стороне google:
                              оценка качества или скорость индексации
    3  нигде                → техническая проблема, ищите причину ниже
```

**Страница, которой нет нигде, и страница, которой нет только в Google, —
это две разные задачи.** Первая не обойдена или отбракована по формальным
признакам, и чинится технически. Вторая обойдена и принята другими, значит
дело в оценке качества конкретным поисковиком, и техническими правками
обычно не лечится. Без разбивки по индексам обе выглядят одинаково.

Страницы, закрытые от индексации намеренно, в «нигде» не попадают.

### Кому уходит уведомление

`notify` показывает состав перед отправкой и тянет его из реестра протокола,
а не из зашитого списка — он меняется:

```
Получат уведомление (реестр indexnow.org):
  amazonbot, bing, internetarchive, naver, seznam, yandex, yep
  не получат → google: не поддерживает IndexNow. Остаются sitemap
               и Search Console
  не получат → baidu: своя система подачи, требует отдельной регистрации
```

Реестр кэшируется на неделю в домашнем каталоге, в CI без сети работает
флаг `--offline`. Про Google сказано прямо: «отправлено» без этой оговорки
создаёт ложное ощущение, что покрыты все.

Ключ вы придумываете сами: 8–128 символов латиницы, цифр и дефиса. Он же
становится именем файла в **корне сайта** — положите его туда через
`--write-key --key-dir ./public`, иначе протокол ответит 403.

## Про ИИ-поиск — честно

Пакет проверяет, что страница не мешает машине взять с себя ответ. Он **не
обещает цитирований** и не может их обещать.

По данным Ahrefs на 75 000 брендов с видимостью в ChatGPT, AI Mode
и AI Overviews сильнее всего коррелируют упоминания на YouTube (0,74)
и брендовые упоминания в вебе (0,71). Количество страниц на сайте —
**0,19**. То есть ровно то, что производит programmatic-конвейер, почти
не связано с попаданием в ответы ИИ. Плюс 76% цитат в AI Overviews —
страницы из топ-10 обычной выдачи.

Вывод, который стоит принять до начала работы: машинная читаемость —
необходимое условие и наша часть работы; попадание в ответы определяется
упоминаниями вне сайта и позицией в обычной выдаче, и это отдельная задача,
не про код.

`llms.txt` пакет не генерирует намеренно: Google публично заявил, что
не поддерживает и не планирует, ни один движок не подтвердил использование
для ранжирования.

## Настройка под свою нишу

Пакет не знает заранее, чем вы торгуете. Виза меряется в SGD и днях, квартира —
в квадратных метрах, станок — в киловаттах и штуках. Поэтому нишевое в код
не зашито, а берётся из двух мест.

**Выводится из ваших данных автоматически.** Единицы измерения, по которым
число в тексте считается фактом первого уровня, извлекаются из датасета:

```
Проект — язык: ru; единицы фактов (из датасета): usd, м²
Проект — язык: en; единицы фактов (из датасета): kg, kw, pcs
```

Настраивать при этом ничего не нужно. Пакет печатает, что он понял про проект,
перед проверкой — молчаливая автонастройка опаснее явной.

**Задаётся в `indexgap.json`** рядом со страницами, если автоопределения
не хватает. Все поля необязательные, пример — в `examples/`:

```json
{
  "extra_fact_units": ["шт", "чел"],
  "vague_anchors": ["здесь", "подробнее"],
  "checks": { "thin_words": 400, "max_click_depth": 4 }
}
```

**Язык учитывается там, где это меняет результат.** В японском, китайском
и тайском нет пробелов между словами: обычный подсчёт даёт три десятка «слов»
вместо двух сотен. Объём для таких языков считается в символах, а пороги длины
title и description — вдвое короче. Язык берётся из разметки страниц,
при необходимости задаётся в конфиге.

**Структура страницы не навязывается.** Стандартный бриф говорит «структура —
под данные строки», а не диктует разделы. Свой шаблон подставляется через
`--brief my-brief.md`.

**Slug для нелатинских письменностей.** Кириллица транслитерируется, диакритика
снимается, длинный ключ обрезается по границе слова с добавлением короткого
хеша — чтобы длинный хвост не схлопнулся в один адрес. Для японского,
арабского и тайского латинский slug не строится: там возвращается устойчивый
хеш. Если нужны осмысленные URL, добавьте в датасет колонку с готовым slug
и укажите `--pattern "{ваша_колонка}/index.md"` — значение подставится как есть.

## Служебные файлы

Рядом со страницами появляется `.indexgap-manifest.json` — состояние lastmod,
очереди IndexNow и список файлов sitemap, которые пакет создал сам. Внесите его
в `.gitignore` статического генератора, чтобы он не уехал в сборку. Кэш реестра
поисковиков лежит в домашнем каталоге и в проект не попадает.

Пакет убирает за собой только те файлы `sitemap-*.xml`, которые создал сам
и записал в манифест. Чужие `sitemap-news.xml` и `sitemap-images.xml` он
не трогает. Отчёт не перезаписывает существующий файл, если это не его
собственный прошлый отчёт. Каталоги сборки (`public`, `dist`, `_site`, `build`,
`out`, `.next`, `node_modules`) при обходе пропускаются.

## Чего он не делает

Не пишет и не переписывает контент — это работа человека или агента.
Не проверяет позиции и частотность. Не ходит в платные сервисы.
Не решает за вас, что публиковать: отбраковку всегда подтверждает человек.

И не заменяет Search Console с Вебмастером — наоборот, приводит к ним.
Если инструмент говорит одно, а Search Console другое, прав Search Console.

## Откалибровано на живых сайтах, а не на фикстурах

Пороги перестали быть догадкой. Их сверили с шестью работающими сайтами —
7 149 адресов из sitemap, 5 041 страница скачана и разобрана, — и этот прогон
изменил сам инструмент трижды.

**Одна беда, а не четыре.** Два сайта из шести отдавали каждую страницу пустой
JS-оболочкой. Пакет честно нашёл 1 099 `js-shell` — и вместе с ними
1 099 `low-uniqueness` и 1 098 `orphan`. Это не три находки, а одна: в HTML
без текста нечего мерить и не по чему ходить. Теперь зависимые проверки
на оболочках не считаются, а их число называется вслух.

**Дубли — это группы, а не страницы.** 588 почти-дублей оказались 72 группами,
в самой большой 24 страницы. «Переписать 588 страниц» — приговор,
«развести 72 темы» — задача на неделю.

**Находка на всех страницах — свойство шаблона.** `vague-anchor` сработал
на 2 970 страницах из 2 970. Виноваты были переключатель языка («中文»)
и ссылка на соцсеть («VK») — короткие по знакам и совершенно информативные.
Длина анкора теперь меряется в своей мере для иероглифики, а любой код,
задевающий больше 90% страниц, помечается как то, что чинится один раз
в шаблоне.

Что именно измерено и как из этого выведены пороги — в шапке
`indexgap/profiles.py`.

Отдельный урок записан в `tests/test_wave2.py`: два теста первой волны прошли
мимо собственных находок, потому что проверяли соседний вариант — `<main>`
вместо `role="main"`, функцию напрямую вместо пути через командную строку.
Тест защищает ровно ту строку, которая в нём записана.
