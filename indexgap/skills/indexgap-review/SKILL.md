# Проверка перед публикацией

```bash
indexgap check ./content --site https://example.com --dataset keywords.csv
```

`--site` — адрес сайта целиком, со схемой. По нему же определяется главная
страница: если её нет среди разобранных файлов, глубина клика не считается,
и команда об этом говорит. Другую главную можно задать через `--home`.

`--dataset` включает сверку фактов с данными строк. Без него текстовые
проверки работают, а сверять числа не с чем.

Отчёт пишется в `indexgap-check.html` и `indexgap-check.json`. Команда `doctor` пишет
в свои файлы и этот отчёт не затирает.

## Что смотреть в первую очередь

Команда сама печатает три верхних причины — начни с них. Полная таблица кодов:

| Код | Что значит | Что делать |
|---|---|---|
| `unsupported-number` | число с единицей проекта, которого нет в данных | почти всегда выдумка — убрать или подтвердить источником |
| `check-by-eye` | числа со словами, которых нет в данных, одной строкой на страницу | просмотреть глазами: часть таких — обычная речь, часть — выдумка |
| `brief-left`, `still-draft` | страница не дописана | дописать, это не косметика |
| `noindex` | страница закрыта от индексации | убрать, если это ошибка шаблона |
| `nosnippet` | запрещён сниппет | без права на сниппет страница не попадёт в ответы ИИ-поиска |
| `canonical-elsewhere` | canonical ведёт на другую страницу | проверить шаблон |
| `orphan`, `unreachable` | нет входящих ссылок / не дойти от главной | добавить ссылки с хабовых страниц |
| `near-duplicate` | совпадение выше порога дубля | переписать под другой интент или оставить одну с canonical |
| `similar` | похожа, но ниже порога дубля | повод посмотреть, **не находка**: canonical по ней не ставят. Разбор потерь её тоже не учитывает |
| `low-uniqueness` | шаблон вытеснил содержание | добавить то, что отличает страницу |
| `template-skeleton` | одинаковые H2 в том же порядке | менять структуру под данные, а не только подстановки |
| `same-opening` | одинаковое начало текста | переписать первый абзац |
| `thin` | нечего индексировать | наполнить или поднять порог в конфиге |
| `no-title`, `no-h1`, `many-h1`, `no-headings` | структура заголовков | поправить шаблон |
| `title-short`, `title-long`, `no-description`, `description-length` | длины | косметика, но дешёвая |
| `duplicate-title`, `duplicate-description` | совпадают у нескольких страниц | склейка в выдаче |
| `deep` | слишком много кликов от главной | поднять выше в структуре |
| `vague-anchor` | анкоры «здесь», «подробнее» | заменить на описательные |
| `source-note` | замечание к файлу: кодировка, фронтматтер | чинить в первую очередь: пока файл читается неверно, остальные находки на нём недостоверны |

Машинная читаемость (её можно выключить флагом `--no-aeo`):

| Код | Что значит |
|---|---|
| `js-shell` | в исходном HTML почти нет текста при куче скриптов; краулеры ИИ-поиска не исполняют JavaScript |
| `answer-preamble` | первый абзац — разгон, а не ответ |
| `answer-short`, `answer-long` | длина первого абзаца вне диапазона цитирования |
| `no-question-headings` | вопросов среди подзаголовков меньше трети |
| `long-paragraph`, `no-structure` | блок трудно процитировать целиком |
| `jsonld-broken`, `jsonld-faq-invisible` | разметка не парсится или не совпадает с текстом |
| `no-date`, `no-author` | нет машиночитаемых даты и автора |
| `ai-crawler-blocked`, `robots-blocks-all` | robots.txt закрывает нужного краулера |
| `robots-unreadable`, `no-robots` | robots.txt не прочитан или не передан |
| `no-answer` | не нашлось ни одного абзаца, который можно процитировать |
| `img-no-alt` | изображения без alt |
| `jsonld-no-type` | в блоке разметки нет `@type` |
| `robots-no-sitemap` | в robots.txt нет строки `Sitemap:` |

robots.txt ищется рядом со страницами и уровнем выше; путь задаётся `--robots`.

## Про выдуманные числа

Это самая важная находка пакета и единственная, где ошибка стоит дороже
пропущенного трафика. Сотня страниц с несуществующими пошлинами и сроками —
это вред человеку, который по ним поедет.

Сверка двухуровневая. Число с единицей, выведенной из датасета (RUB, м², кВт),
идёт как `critical`. Число с любым другим словом — «12 лет», «3500 заказов»,
«25 тонн» — собирается в одну строку `check-by-eye` уровня «мелочь»: сигнал
слабее, но именно там прячется бо́льшая часть выдумок.

Прощается число из своей строки датасета и постоянные величины сайта — те,
что повторяются в одной колонке у большинства строк (фиксированная пошлина,
срок гарантии). Число, которого нет ни там ни там, не прощается никогда,
сколько бы страниц его ни повторяло.

Следи за строкой «Сверено с датасетом: N из M». Если N меньше, разбирайся:
страница либо не сопоставилась, либо подошла сразу к нескольким строкам —
во втором случае сверка честно не делается, и об этом написано отдельно.

Ложные срабатывания возможны: число может быть законным и просто отсутствовать
в датасете. Разбирай каждое с человеком, не правь молча.

## Порог для CI

```bash
indexgap check ./content --site https://example.com --dataset keywords.csv --strict
```

Ненулевой код возврата при критичных находках — чтобы конвейер не публиковал
недописанное.

## Наряды на починку

```bash
indexgap brief ./content --site https://example.com --dataset keywords.csv --write
```

Раскладывает те же находки заданиями в `indexgap-briefs/`: к каждой добавлено
«что делать» императивом, пороги профиля и строка датасета — единственный
разрешённый источник чисел для этой страницы.

Читать наряды в этом порядке:

1. `_template.md` — то, что срабатывает почти на всех страницах. Это одна
   правка в шаблоне, а не сотни правок в страницах. Начинать всегда отсюда:
   после неё часть остальных нарядов исчезает сама.
2. `_site.md` — robots.txt, разметка, связи языковых версий.
3. `_duplicates/group-NNN.md` — группы почти-дублей. Наряд выписан на группу:
   одну страницу из неё починить нельзя. Оставить одну, остальные развести
   по разным интентам, ссылками между собой **не связывать**.
4. Остальные файлы — постранично, самые тяжёлые первыми (`--limit`, по
   умолчанию 50; `0` — все).

Без `--write` это пробный прогон: команда говорит, сколько нарядов выпишет
и куда, и не создаёт ничего.

Наряды перезаписываются при каждом прогоне — это отчёт, а не исходник.
Свои правки держи в страницах.

**Пакет не пишет текст и не должен.** Он формулирует задачу; текст пишешь ты.
Причина не в осторожности: главная проверка сверяет числа на странице
со строкой датасета, и если бы те же числа подставил сам пакет, проверка
проверяла бы себя и всегда была бы зелёной. Чисел, которых нет в строке
датасета, в починенной странице быть не должно — если данных нет, раздел
не пишется вовсе.
