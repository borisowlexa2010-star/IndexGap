# Проверка перед публикацией

## Где делать правку

Если страницы собирает скрипт, статический генератор или выгрузка из CMS,
любая правка идёт в шаблон, датасет или генератор — никогда в собранные файлы.
Следующая сборка их перезапишет, и `check` позеленеет ровно до неё. Сначала
найди команду сборки (не уверен — спроси). Цикл: правка в источнике →
пересборка → `indexgap check`.

Строка `File:` в наряде называет собранный файл, чтобы было видно, какой
шаблон и какая строка датасета дали страницу. Это не файл для правки. Напрямую
правят только страницы, которые сами и есть источник: Markdown, написанный
по заготовкам `indexgap plan`.

## Перед первой командой

1. `indexgap init` в корне проекта пишет `indexgap.json`; дальше хватает `indexgap check` без флагов.
2. Покажи человеку, что `init` угадал: каталог страниц, адрес сайта, профиль, датасет. Попроси подтвердить.
3. Каталог страниц — тот, что на сайте отдаётся как `/`. Ошибка здесь даёт вердикт «все страницы сироты».
4. Профиль (`catalog`, `events`, `ugc`, `product`) меняет пороги и выключает проверки — его тоже подтверждает человек.
5. Нет команды `indexgap`: `pipx install indexgap`; из исходников — `pipx install -e <путь>` или `PYTHONPATH=<путь> python3 -m indexgap`.

## Запуск

```bash
indexgap check ./out --site https://example.com --dataset keywords.csv
```

`--site` — адрес сайта целиком, со схемой. По нему определяется главная
(другая — `--home`); если её нет среди файлов, глубина клика не считается.
`--dataset` включает сверку фактов: без него сверять числа не с чем.

Отчёт пишется в `indexgap-check.html` и `indexgap-check.json`. `--out report.json`
пишет данные в `report.json`, а HTML рядом, в `report.html`. `doctor` пишет
в свои файлы и этот отчёт не затирает.

## Что смотреть в первую очередь

Начни с `unsupported-number` и `unfilled-slot`, где бы они ни стояли в выводе:
три верхних причины команда печатает по числу находок, а не по важности.

| Код | Что значит | Что делать |
|---|---|---|
| `unsupported-number` | число с единицей проекта, которого нет в данных | почти всегда выдумка — убрать или подтвердить источником |
| `unfilled-slot` | незаполненная подстановка: `{{city}}`, `{city}`, `%CITY%`, `undefined`, `NaN`, `[City]` (если это колонка датасета), lorem ipsum — critical; пустое место в title или заголовке — warning | найти в генераторе, откуда пришло пустое значение |
| `llm-leftover` | вместо текста ответ модели: отказ, «As an AI language model», «Certainly! Here is» | перегенерировать страницу, поправить промпт |
| `mojibake` | UTF-8, прочитанный как Latin-1: `CafÃ©`, `Ð¿Ñ€Ð¸` | найти шаг конвейера, где потерялась кодировка |
| `check-by-eye` | числа со словами, которых нет в данных, одной строкой на страницу | просмотреть глазами: часть — обычная речь, часть — выдумка |
| `brief-left`, `still-draft` | страница не дописана | дописать, это не косметика |
| `noindex` | страница закрыта от индексации | убрать, если это ошибка шаблона |
| `nosnippet` | запрещён сниппет | без сниппета страница не попадёт в ответы ИИ-поиска |
| `canonical-elsewhere` | canonical ведёт на другую страницу | проверить шаблон |
| `orphan`, `unreachable` | нет входящих ссылок / не дойти от главной | ссылки с хабов раздела; хабы собираются генератором — чинить список ссылок в нём |
| `broken-link` | внутренняя ссылка на страницу, которой нет в сборке | убрать ссылку из шаблона или сгенерировать страницу |
| `near-duplicate` | совпадение выше порога дубля | см. «Почти-дубли» ниже |
| `similar` | похожа, но ниже порога дубля | повод посмотреть, **не находка**: canonical по ней не ставят |
| `low-uniqueness` | шаблон вытеснил содержание | добавить данные своей строки |
| `template-skeleton` | одинаковые H2 в том же порядке | менять структуру под данные, а не только подстановки |
| `same-opening` | одинаковое начало текста | переписать первый абзац в шаблоне |
| `thin` | мало текста | см. «Тонкие страницы» ниже |
| `no-title`, `no-h1`, `many-h1`, `no-headings` | структура заголовков | поправить шаблон |
| `title-short`, `title-long`, `no-description`, `description-length` | длины | дёшево; description собирать из полей строки, без новых чисел |
| `duplicate-title`, `duplicate-description` | совпадают у нескольких страниц | склейка в выдаче; часто это строки с одним интентом |
| `deep` | слишком много кликов от главной | поднять выше в структуре |
| `vague-anchor` | анкоры «здесь», «подробнее» | заменить на описательные |
| `source-note` | замечание к файлу: кодировка, фронтматтер | чинить первым: пока файл читается неверно, остальные находки на нём недостоверны |

Что сворачивается само: закрытый раздел (от 20 страниц, из них не меньше 90 %
под noindex) — одна заметка, а не находка на каждой странице; noindex вместе
с canonical на одной странице — одна находка; версия для печати или вариант
с canonical на открытую страницу того же языка — справочная строка.

Машинная читаемость (выключается флагом `--no-aeo`):

| Код | Что значит |
|---|---|
| `js-shell` | в исходном HTML почти нет текста при куче скриптов; краулеры ИИ-поиска не исполняют JavaScript |
| `answer-preamble`, `answer-short`, `answer-long`, `no-answer` | первый абзац — разгон, вне диапазона цитирования или не найден |
| `no-question-headings` | вопросов среди подзаголовков меньше трети |
| `long-paragraph`, `no-structure` | блок трудно процитировать целиком |
| `jsonld-broken`, `jsonld-faq-invisible`, `jsonld-no-type` | разметка не парсится, не совпадает с текстом или без `@type` |
| `no-date`, `no-author` | нет машиночитаемых даты и автора. Дата — настоящая дата публикации или обновления из данных, не дата сборки |
| `robots-blocks-page` | правило Disallow в robots.txt закрывает страницу из сборки (critical) |
| `ai-crawler-blocked`, `robots-blocks-all` | robots.txt закрывает нужного краулера или весь сайт |
| `robots-unreadable`, `no-robots`, `robots-no-sitemap` | robots.txt не прочитан, не найден или без строки `Sitemap:` |
| `img-no-alt` | изображения без alt |

robots.txt ищется рядом со страницами и уровнем выше; путь задаётся `--robots`.
Он должен лежать в корне публикации — в каталоге, который отдаётся как `/`;
если этот каталог собирается, robots.txt выпускает генератор. Файл уровнем
выше, который не публикуется, проверку удовлетворит, а сайт — нет.
`X-Robots-Tag: noindex` читается из `_headers`, `netlify.toml` и `vercel.json`.

Языковые версии:

| Код | Уровень | Что значит |
|---|---|---|
| `hreflang-no-self` | critical | в кластере нет самой страницы — кластер невалиден |
| `hreflang-no-return` | critical | связь не взаимная, односторонняя отбрасывается |
| `hreflang-canonical-conflict` | critical | canonical ведёт на другой язык, а hreflang называет версии равными |
| `hreflang-static-cluster` | critical | шаблон печатает один и тот же кластер на всех страницах |
| `translations-parked` | critical | переводы закрыты noindex с canonical на оригинал; одна строка с числом по языкам — решить по каждому языку |
| `hreflang-missing` | warning | у сайта несколько языков, а страница о версиях молчит |
| `hreflang-bad-code`, `hreflang-lang-mismatch` | warning | неверный код или пустой href; язык не совпадает с текстом |
| `hreflang-target-blocked` | warning | кластер ведёт на закрытую от индекса страницу |
| `hreflang-unknown-target` | info | адрес из кластера не найден среди страниц |
| `stale-closed` | info | дата прошла, а страница уже закрыта от индекса — так и надо |

## Про выдуманные числа

Самая важная находка пакета: сотня страниц с несуществующими пошлинами
и сроками — вред человеку, который по ним поедет.

Число с единицей из датасета (RUB, м², кВт) идёт как `critical`. Число
с любым другим словом — «12 лет», «3500 заказов» — собирается в строку
`check-by-eye`: сигнал слабее, но выдумки прячутся там. Прощается число
из своей строки и постоянные величины сайта — те, что стоят в одной колонке
у большинства строк. Остальное не прощается, сколько бы страниц его ни повторяло.

**Каждая сгенерированная страница должна называть свою строку.** В Markdown —
`keyword:` во фронтматтере, в HTML — `<meta name="keyword" content="…">`
в шаблоне. Иначе строка ищется по slug и заголовку и часто не находится.
Если N в строке «Сверено с датасетом: N из M» меньше числа страниц строк, сначала
почини привязку: чистая сверка на трёх страницах из сорока ничего не значит.
Хабы и главная без строки — это нормально.

Число в наряде нормализовано (`1200`, `15 %`), на странице оно может стоять
как `1,200` или `15%` — ищи в шаблоне оба вида. Ложные срабатывания возможны:
число бывает законным и просто отсутствует в датасете. Разбирай с человеком.

## Порог для CI

```bash
indexgap check --strict                                    # ненулевой код при critical
indexgap check --out indexgap-baseline.json                # один раз; файл закоммить
indexgap check --baseline indexgap-baseline.json --strict  # падает только на новых critical
```

GitHub Action: `uses: borisowlexa2010-star/IndexGap@v1.13.1` с `root`, `site`,
необязательными `baseline` и `args`.

## Наряды на починку

```bash
indexgap brief ./out --site https://example.com --dataset keywords.csv --write
```

Раскладывает находки заданиями в `indexgap-briefs/`: «что делать», пороги
профиля и строка датасета — единственный разрешённый источник чисел. Без
`--write` — пробный прогон. Наряды перезаписываются при каждом прогоне — это
отчёт; свои правки держи в источнике, из которого собираются страницы.
В конце наряда — та же команда проверки, что его выписала, с `--dataset`
и профилем; запускай её после пересборки. Без `--dataset` сверка фактов молча
выпадает.

Порядок:

1. `_template.md` — то, что срабатывает почти на всех страницах: одна правка
   в шаблоне вместо сотен. Его может не быть (меньше 20 страниц, или хабы
   разбавили долю) — тогда одинаковый код с одинаковым текстом на большинстве
   постраничных нарядов всё равно одна правка шаблона.
2. `_site.md` — robots.txt, разметка, связи языковых версий.
3. `_duplicates/group-NNN.md` — группы почти-дублей, см. ниже.
4. Постраничные наряды, самые тяжёлые первыми (`--limit`, по умолчанию 50; `0` — все).

**Почти-дубли.** Если страницы группы собраны из *разных* строк датасета
(другой город, услуга, товар), дублирует их шаблон, а не интент. Чини шаблон:
больше данных своей строки, разделы, которые зависят от данных. Canonical
между такими страницами не ставь никогда — выпадут настоящие страницы.
Canonical или склейка — только для строк с одним интентом; их показывает
`indexgap plan`, и чинится это удалением лишней строки из датасета. Ссылки
между дублями — не починка (ссылка не делает страницы разными), но обычную
навигацию по соседям и хабам оставь.

**Тонкие страницы (`thin`).** Хаб, листинг и главную судят по ссылкам, а не
по словам: закрывать их от индекса нельзя. Страницу строки наполни фактами
из её строки; если фактов нет — спроси человека, нужна ли страница вообще.
Порог — `checks.thin_words` в `indexgap.json`; чтобы заглушить находку для
законно короткого типа контента, его **понижают**. Воду ради порога не пиши.

**Пакет не пишет текст и не должен.** Главная проверка сверяет числа на
странице со строкой датасета; если бы их подставлял сам пакет, проверка
проверяла бы себя. Чисел, которых нет в строке, в починенной странице быть
не должно — нет данных, нет и раздела.
