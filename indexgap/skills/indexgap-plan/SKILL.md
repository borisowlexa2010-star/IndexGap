# Планирование конвейера

```bash
indexgap plan keywords.csv --keyword keyword
```

Если пакет не установлен (`pip install -e .` в его каталоге), то же самое
делает `python3 -m indexgap plan …`, запущенный из каталога пакета.

Показывает, сколько строк дойдёт до генерации и что отброшено: точные дубли,
коллизии slug, одинаковые интенты. Номер строки в отчёте — как в файле,
считая шапку.

**Интенты — главное.** Два ключа с одним смыслом дадут две почти одинаковые
страницы, и поисковик оставит в индексе одну. Не создать вторую дешевле,
чем потом чинить canonical.

Одинаковым интентом считается совпадение значимых слов после нормализации
словоформ: «виза в сингапур» = «сингапур виза» = «визы в сингапуре».
«виза в сингапур для россиян» — уже другой интент: в нём есть слово,
которого нет в первом. Оставляется первая строка группы.

Покажи человеку список отброшенного и спроси, согласен ли он. Не решай сам:
иногда одинаковый по словам ключ — отдельный интент, который он видит,
а алгоритм нет. Полный разбор с номерами строк: `--json plan.json`.

Когда согласовано:

```bash
indexgap plan keywords.csv --keyword keyword --out-dir content --write
```

В каждом файле фронтматтер и бриф с данными строки. Существующие файлы
не перезаписываются — команду можно запускать повторно; сколько пропущено,
команда говорит.

**Не удаляй `keyword` из фронтматтера при написании страницы.** По нему потом
сверяются факты: без него проверка ищет строку по slug и заголовку, а при
неоднозначности честно отказывается сверять.

**Убери `status: draft`, когда страница дописана.** Заготовка помечена
черновиком намеренно: пока метка стоит, страница не попадёт ни в sitemap,
ни в очередь IndexNow, а `check` покажет её как незаконченную. Снятие метки —
последний шаг написания, а не косметика.

## Что делать с отбраковкой

| Причина | Что это значит |
|---|---|
| точный дубль ключа | строка повторяется буквально |
| тот же интент, что и у другой строки | см. выше, оставлена первая |
| slug совпадает с «…» | разные ключи дают одинаковый адрес |
| пустой ключ | в колонке ключа пусто |
| ключ не содержит ни одной буквы или цифры | мусор вроде `---` или `%%%` |

По умолчанию строки с частично пустыми колонками **не отбраковываются** —
команда только предупреждает, какая колонка пуста и в скольких строках.
Если для этого проекта неполные строки бесполезны, включи порог явно:
`--min-filled 0.7`.

## Бриф под нишу

Стандартный бриф намеренно не диктует структуру страницы — она у каждого
бизнеса своя. Если для этого проекта структура известна и повторяема
(например, карточка товара), напиши свой шаблон и подставь его:

```bash
indexgap plan keywords.csv --keyword keyword --out-dir content \
    --brief my-brief.md --write
```

В шаблоне доступны `{keyword}`, `{keyword_yaml}` (то же в кавычках, для
фронтматтера), `{variables}`, `{min_words}`, `{min_links}`, `{title_min}`,
`{title_max}`, `{desc_min}`, `{desc_max}`. Любая другая фигурная скобка —
ошибка; если скобки нужны как текст (например пример JSON-LD), удвой их:
`{{` и `}}`.

## Адреса страниц

Для нелатинских письменностей slug превращается в короткий хеш. Если нужны
читаемые URL, заведи в датасете колонку с готовым slug и укажи
`--pattern "{твоя_колонка}/index.md"` — значение колонки подставляется как
есть, без повторной транслитерации. Колонку можно назвать и просто `slug`:
собственное значение из датасета важнее вычисленного.

Пустое значение колонки в шаблоне — это ошибка записи, а не «файл в корень»:
такие строки пропускаются с объяснением. Выйти за пределы `--out-dir`
шаблон не может.
