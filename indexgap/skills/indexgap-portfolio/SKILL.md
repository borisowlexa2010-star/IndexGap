# Портфель

```bash
indexgap portfolio projects.json --reports ./reports
```

Отдельные отчёты отвечают на вопрос «что не так у этого сайта». Портфель
отвечает на другой, которого в них не видно: **что ломается одинаково везде.**
Одна и та же дыра в перелинковке на четырёх разных нишах — это уже не баг
проекта, а свойство того, как эти проекты собираются. Чинить надо привычку.

## Описание портфеля

Обычный JSON, пути внутри — относительно самого файла:

```json
{
  "projects": [
    {"name": "visa", "root": "../visa/content", "site": "https://visa.example",
     "profile": "catalog", "dataset": "../visa/keywords.csv"},
    {"name": "eventiq", "root": "../eventiq/events", "site": "https://eventiq.example",
     "profile": "events"},
    {"name": "rumors", "root": "../rumors/content", "site": "https://rumors.example",
     "profile": "ugc"},
    {"name": "reloca", "root": "../reloca/out", "site": "https://reloca.example",
     "profile": "product"}
  ]
}
```

Обязательны только `name`, `root` и `site`. Необязательные: `profile`,
`dataset`, `sitemap`, `robots`, `config`, `home`, `keyword`, `out`.

Ошибка одного проекта не роняет прогон: она попадает в отчёт отдельной
строкой, остальные считаются дальше.

**`root` каждого проекта обязан соответствовать корню его сайта** — это
то же правило, что и для одиночной проверки, и здесь оно ошибается чаще,
потому что проектов много. Если у одного из них вдруг «все страницы сироты»,
сначала проверь путь.

## Профили

Пороги у разных типов контента разные не по вкусу, а по существу. 250 слов —
норма для гайда и приговор для карточки события; сверка фактов бессмысленна
там, где датасета нет вовсе. `indexgap profiles` печатает все четыре:

| Профиль | Для чего | Что меняется |
|---|---|---|
| `catalog` | страницы из строк данных: города, услуги, товары | сверка фактов главная, порог дубля 0,80, тонкая страница — меньше 250 слов |
| `events` | афиша, расписания, площадки | порог дубля 0,88 (две карточки одного тура законно похожи), тонкая — меньше 120 слов, включается проверка `stale-event` |
| `ugc` | лента, обсуждения, отзывы | сверка фактов выключена целиком, порог дубля 0,92, шаблонность почти не показательна |
| `product` | десятки лендингов, а не тысячи страниц | дубли не главное, окупается AEO-часть: прямой ответ, вопросные подзаголовки, разметка |

**Профиль ниже того, что человек написал руками.** Значение в
`indexgap.json` всегда сильнее пресета.

Для одного сайта профиль задаётся флагом:
`indexgap check ./content --site … --profile events`.

## Что говорить человеку по результату

**Про общие грабли — в долях, а не в штуках.** Сто находок на трёх тысячах
страниц и десять на двадцати — одна болезнь разной громкости. В таблице они
стоят рядом именно в процентах, и это то место, где видно системную причину.

**Про site-level находки — отдельно.** robots.txt и разметка относятся к сайту,
а не к страницам; доля страниц для них бессмысленна, поэтому в таблице
просто «есть». Не путай их с массовыми находками.

**Про `ugc` — что проверка не делалась.** Если в ленте нет находок по фактам,
это не «всё хорошо», это «сверять не с чем». Пакет пишет это отдельной строкой;
проговори её вслух, иначе человек решит, что проверено.

**Про `events` — что дата важнее дублей.** Прошедшее событие, открытое для
индексации, — не потеря трафика, а удар по доверию: человек приедет по вашей
странице на несуществующее мероприятие. Проверка `stale-event` про это,
и у неё есть льготный период: отчёт о прошедшем — законный контент.

**Про «личное у каждого».** Находки, встретившиеся ровно в одном проекте,
чинятся по месту. Не тащи их в общие выводы — они про конкретный сайт.
