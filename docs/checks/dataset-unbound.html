dataset unbound

warning dataset-unbound Invented facts

The dataset was given, but fewer than half of the pages were bound to its rows — so the numbers on the rest were never checked against anything, and a clean fact check means nothing. A page is bound by `keyword:` in its front matter, by ``, by a `slug`/`url`/`path` column in the dataset matching its address, by its folder name, or by its title. The run also lists the dataset rows that have no page at all: a generation failure or a filter.

What indexgap reports

The finding reads:

warning  dataset-unbound  the dataset check covered … of … pages — the numbers of the rest were not checked. Bind pages to rows: a slug or url column in the dataset, `keyword:` in the front matter or <meta name="keyword"> in the template

How to fix it

Bind pages to rows: add a slug or url column with the page address to the dataset, or write the row key into `keyword:` in the front matter, or <meta name="keyword"> in the template.

How it behaves at scale

This is a site-level finding: it belongs to the site, not to any one page, and is reported once however many pages are audited.

Finding it

pipx install indexgap
cd your-project
indexgap init
indexgap check

Then indexgap brief turns every finding on this page into a work order in indexgap-briefs/, with the thresholds the result has to satisfy and the command to check it.
